# Decision: Cut 0.2.0 by Hand

Version: 0.1.0
Status: Accepted

## Context

eleventy-website-vishpala-com uses the `eleventy-site` layout (uc-automa 0037), which is on `main` but in no release. `automa_version` in `.uc-automa.yaml` names a release, `X.Y.Z`, so the site stays pinned to 0.1.0 and conforms only where uc-automa is installed from a checkout of `main`.

The scope approved on 2026-10-11 for 0.2.0 is not built: the `uc-automa release` subcommands (uc-automa 0026), the release wheels and their verification record (uc-automa 0027 and 0028), `release-keys/` (uc-automa 0030), the test platform's runs (uc-automa 0031) and the SSH signatures (uc-automa 0032). Those decisions name 0.2.0 as the release that brings them. uc-automa 0.1.0 was cut by hand, as an annotated tag without a signature.

## Decision

- uc-automa 0.2.0 is cut by hand, as 0.1.0 was: the `[Unreleased]` section of `CHANGELOG.md` becomes `[0.2.0]`, `VERSION` and the README's own install references change to 0.2.0, those three files are committed as `Release 0.2.0`, and `v0.2.0` is an annotated tag, `uc-automa 0.2.0`, without a signature.
- It carries no wheels, no verification record and no signatures. Its install is the README's install from the tag, as 0.1.0's is.
- Wherever uc-automa 0026, 0027, 0028, 0030, 0031 and 0032 say that uc-automa 0.2.0 brings the release ceremony, the wheels, the verification runs, `release-keys/`, the test platform's runs, the SSH release key or the signed tags, read uc-automa 0.3.0. Those records keep their text and their versions.
- The roadmap's scope approved for 0.2.0 becomes the scope of 0.3.0, unchanged. Versions of other repositories, such as uc-portage 0.2.0, are unaffected.

## Alternatives considered

**Cut 0.1.1.** Rejected. A new layout, a new directive and new subcommands are a minor change, and a patch version would hide them.

**Wait for the full ceremony.** Rejected. The ceremony needs the verification runs and the release key, and a site would wait on them for one layout.

**Edit 0026, 0027, 0028, 0030, 0031 and 0032 in place.** Rejected. How a decision's version changes after it is accepted is not yet decided, and a later record changing an earlier one is how 0028 and 0032 already work.

## Consequences

- eleventy-website-vishpala-com can pin `automa_version: 0.2.0`.
- The README documents no `Install offline` section and no tag verification for 0.2.0, since neither exists yet.
- The ceremony's first release is 0.3.0, so its release order with uc-portage 0.2.0 is as the roadmap records it, with 0.3.0 in place of uc-automa 0.2.0.
